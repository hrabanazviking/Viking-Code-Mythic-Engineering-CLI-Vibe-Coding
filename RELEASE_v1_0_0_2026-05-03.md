## How to tag and ship

The release pipeline (`.github/workflows/release.yml`, PH-19.7) runs on tag push:

1. Verify `pyproject.toml` version is `1.0.0` (already done in this commit).
2. Verify `mythic_vibe_cli/__init__.py:__version__ == "1.0.0"` (already done).
3. Verify `CHANGELOG.md` has a `## [1.0.0] — 2026-05-03` entry (already done) and a fresh empty `## [Unreleased]` block above it (already done).
4. Verify the manual gates in `docs/RELEASE_CHECKLIST.md` are satisfied (compatibility-policy review, install checks).
5. **Tag and push:**

```bash
git tag v1.0.0
git push origin v1.0.0
```

The workflow will then:

- Build wheel + sdist + offline wheelhouse + SBOM.
- Validate via `twine check`.
- Publish to PyPI via OIDC trusted publishing (no long-lived token).
- Create a GitHub Release with wheel, sdist, wheelhouse,
  SBOM, and `SHA256SUMS` / `SHA512SUMS` attached.
- Open auto-update PRs against the `homebrew-mythic` tap and
  the `scoop-mythic` bucket (per the templates in
  `packaging/`).

Per-release manual gates after the workflow finishes are
listed in `docs/RELEASE_CHECKLIST.md` "Tag-driven distribution"
section.
